# Architecture and process decisions

One row per decision that changes how NoteForge is built, tested, or released.
Newest first. The roadmap's decision points (docs/roadmap/NOTEFORGE_2_ROADMAP.md §6)
are recorded here when they are taken.

| Date | Decision | Why | Revisit when |
| --- | --- | --- | --- |
| 2026-10-04 | Activate per-note storage automatically on first open and capture later legacy saves as review items (NF-DUR-MIG-01 = C, Dave 2026-10-04). `my-notes-app` stays at IndexedDB version 1; activation reads both legacy backends and never writes their `notes`, `config` or `schemaVersion`. Capture records each changed legacy note beside the current note in the conflict UI; deletions can only be kept and settings are archived unapplied. Supersedes the 2026-10-04 row that kept activation disabled; supervised cutover (A) and hold (B) were declined. | The application cannot prove that every old session is gone, so preventing old writes is not achievable; capturing them keeps each acknowledged edit that is still in the legacy store at the next capture, without user-operated steps. Accepted residual: two legacy windows can overwrite each other's whole-vault saves before a capture, as in 7114047, so the earlier edit can be lost before it is captured; the last legacy state is captured. Never upgrading the database keeps old clients off VersionError and the fallback. Qualified against the actual 7114047 build in Chromium, Firefox, WebKit, Chromium BFCache and native Safari (`durable_writes.md`). | A legacy save still present in the legacy store at a capture goes uncaptured: disable activation, keep the evidence and return to Dave. Or 7114047 clients are no longer plausible: retire capture. |
| 2026-10-04 | A window's vault sequence advances only with its own consecutive commits; other windows' commits are adopted through refresh. Planned operations keep the vault-wide sequence precondition (review finding R5 disproved). | Advancing to a jumped sequence, or re-reading the marker before a plan, would let a plan skip a commit this window has not seen and make refresh report no change. The lag is the signal that a refresh is needed, and the preview refresh path already re-plans. | Measured false stale-plan rejections justify a narrower dependency check that still detects unseen commits. |
| 2026-10-04 | Shell and precache budgets rebaselined to 99,328 B and 281,600 B gzip (NF-DUR-BUDGET-01 = A, Dave 2026-10-04): measured + 10% on the final Phase 1 candidate exceeded Dave's 97/275 KiB caps, so the caps apply. Other routes unchanged. | Durable writes, exact save state, startup recovery, activation and capture must load before editing; lazy splitting cannot shrink the complete offline cache. Budget log in `performance_budgets.md`. | Any route needs more: a new approval. Phase 2 feature loading should restore headroom where it can. |
| 2026-10-04 | Reject automatic migration based only on worker takeover, claim/drain or an IndexedDB version upgrade. Keep production activation disabled. Proposed supervised cutover NF-DUR-MIG-01 remains Open in durable_writes.md. | Actual Firefox and native Safari legacy fallback clients can survive tested barriers and acknowledge divergent writes. A normal Firefox restart pass does not establish cross-browser fencing. | A complete boundary is proved, or the user explicitly selects and qualifies a supervised session-retirement contract. No budget or migration approval is inferred. |
| 2026-10-04 | Database and property-index notifications coalesce sidebar redraws to one animation frame; explicit renders cancel the queued redraw. Property reconciliation copies only requested changed sources, skips metadata-only changes, and rebuilds missing indexes on replacement Note objects. Sorts reuse one locale comparator. | Production editor/history qualification exposed WebKit input delays from full-vault copying, unnecessary YAML work and repeated sidebar redraws during metadata changes. Writes, editor refresh and conditional mutation checks remain immediate. Derived presentation reads the latest model at its frame. | The maintained 1000/5000-note production tests or interaction budget regress; future view indexes may narrow sorting further without weakening planned-commit preconditions. |
| 2026-10-04 | Basic startup recovery ships in the shell; a separate storage archive preserves every object store and namespaced fallback value without portable conversion. It reads the actual database version without upgrading. | Recovery cannot depend on its own failed lazy asset. Schema-aware note export omits future namespaces and history. A versioned structured-value graph preserves binary/source identities while unsupported values fail explicitly; independent backends and browser key-generator limits remain disclosed. | A schema-compatible archive restore workflow is authorized, or measured archive size requires streaming. Old-client migration activation remains separately gated. |
| 2026-10-04 | Failed first loads open a read-only recovery surface before any editor or writer starts. Validate legacy source before migrations or Map projection; retain loaded source and malformed localStorage bytes, and disable portable conversion for unsupported data. Unreadable storage has no export until reload succeeds. | Future schema conversion and duplicate-ID projection can silently lose source. Recovery must distinguish unreadable data from an empty vault. Runtime refresh still rejects without clearing the live model or drafts. | Add full storage/archive export for future namespaces; recovery source is explicitly not a verified portable backup. Migration activation still requires old-client proof. |
| 2026-10-04 | Newly introduced live titles and aliases are validated inside the note transaction against the final batch and saved owners. Existing ambiguity stays editable; explicit import exceptions follow only an unchanged queued identity. | Local duplicate checks race across windows. A transaction cursor for identity changes avoids another persistent index and migration; ordinary content writes do not scan names. Competing Inbox creation retains a recoverable draft instead of silently retargeting it. | Measured identity-operation cost warrants an index, or explicitly authorized collaboration changes name ownership semantics. |
| 2026-10-03 | Editors distinguish their rendered/submitted source from buffered typing. Planned writes, replacement and conflict resolution synchronously flush every mounted editor before precondition checks and before advancing committed versions. Authoritative reopen preserves later drafts. | Comparing editor content only to the changed store mistook a clean obsolete view for a draft; cancelling debounce on completion discarded actual typing. Preserving the original version/generation makes intervening drafts conflict explicitly. | Exact acknowledgement UI and remaining caller/upgrade qualification pass; a future editor core must retain this contract and composition ownership. |
| 2026-10-03 | Planned mutation views retain user intent after a typed stale-plan rejection and require an explicit guarded storage refresh plus a new apply action. Properties binds saves to the source shown at load; reconciliation detaches the plan, decisions, source readers and mutation token before asynchronous preparation. | A rejected plan must not be silently recomputed under its old confirmation. A newer scan must not lend its token to an older in-flight batch. Refresh changes what is reviewed, not what is saved. | Remaining lifecycle, failure and derived-view acceptance is complete; narrower dependencies are justified by measured false conflicts. Production activation remains independently gated. |
| 2026-10-03 | History restore carries the detached destination and mutation token from the reviewed comparison through confirmation and safety capture. Stale plans have a stable error code and require an explicit storage refresh plus renewed confirmation. | Capturing the token after confirmation allowed a newer acknowledged edit to become an unreviewed restore target. Preserving the original preview protects source and makes recovery choices reviewable. | Apply the same UI contract to remaining planned callers; refine conservative sequence dependencies only with measured evidence and phantom-dependency coverage. |
| 2026-10-03 | Workspace tabs/panes/scroll, collapsed hierarchy and recent-note navigation live in per-window sessionStorage; shared preferences remain versioned vault configuration. Existing legacy layout seeds a new window without being rewritten or treated as current shared state. | Navigation is not a competing edit to another window's workspace. Reload restores each window independently, while denied storage retains the current session in memory and announces reduced layout persistence without blocking durable note writes. | Product requirements add explicit cross-session workspace profiles. Such profiles need stable identities and explicit save/open actions, rather than restoring shared last-writer-wins navigation. |
| 2026-10-03 | Window refresh adopts a consistent snapshot only when the entire local window is clean, checking model baselines, queues, editor ownership and modal state again after the read. Post-commit hints and resume/visible polling trigger checks; they never provide concurrency control. | Dirty drafts keep their original generation/version. A delayed read cannot replace later edits or roll back a newer refresh. Conservative whole-window deferral is preferable to accidentally assigning a new base to a stale draft; source replacement also resets incompatible undo history. | Measured latency or persistent conflicts justify independent per-note refresh. Such a change must retain each draft's original generation and cover every pending editor/config owner. |
| 2026-10-03 | Conflict resolution uses a private immutable preview, vault sequence and exact conflict fingerprint, then archives the conflict and replaced values in the same transaction as the choice. A later local draft keeps its original base. Recovery UI and revision leases load on demand. | A resolution is itself a destructive planned mutation; clearing a warning must not erase the only draft or acknowledge a different choice. Explicit copies preserve portable source without guessing how Markdown should merge. | Real editor/migration acceptance passes; archive growth needs measured retention/export UX before release. |
| 2026-10-03 | Durable-write repair uses per-note versions, field-level config preconditions, tombstones and vault generations, checked in the same IndexedDB transaction as the write. Planned operations also require the observed vault sequence. Production activation remains gated pending old-client proof; implementation details and incomplete gates are in `docs/implementation/durable_writes.md`. | Whole-vault snapshots lose unrelated acknowledged edits. Advisory locks do not validate stale plans. Explicit conflicts preserve source without introducing a CRDT or replacing the editor. A conservative sequence can reject unrelated changes but cannot silently apply a changed plan. | Old/new build compatibility is proved before activation; narrower plan dependencies are considered only after measured false conflicts justify them. |
| 2026-09-27 | Subject areas open as main-area views, not workspace tabs: `MainViewHost` (`src/components/main-view.js`) gives Tasks, Calendar, Archive, and Trash Modal's interface but shows them in `.main` in place of the editor, and `App.setView` owns which one shows (editor, graph, tasks, calendar). Section ids (`#task-dashboard-overlay`, `#calendar-overlay`, `#archive-overlay`, `#trash-overlay`) are kept for tests. | Satisfies WEB-2 (subject areas are not modals) without changing the persisted workspace tab model, and matches how Graph already works. | Workspace tabs learn non-note content (Phase 3 views), at which point these views can become tabs. |
| 2026-09-27 | Menu keyboard behavior lives in `src/ui/menu-nav.js` (`moveMenuFocus`: wrap-around arrows, Home/End, typeahead), shared by the More actions menu and the block action menu. Each menu keeps its own Escape/Tab handling because focus returns to different places. | The block action menu was the second menu-like widget, the revisit condition of the hand-written-menu decision. About 25 shared lines do not justify Zag. | A widget needs submenus or checkable items: reconsider Zag's menu machine. |
| 2026-09-27 | The overflow menu is a hand-written WAI-ARIA menu button (`role=menu`, labelled groups, roving focus, typeahead), not a Zag.js machine. Its fifth group is App (Settings), not Help. | One menu needed about 40 lines; Zag's menu machine would cost several KiB against a shell route with 4 KiB of headroom. NoteForge has no Help content yet. | A second menu-like widget (slash menu v2, block action menu) needs the same behavior: extract a shared primitive, or adopt Zag if the machines pay for themselves. |
| 2026-09-27 | Design tokens in three tiers (`src/styles/tokens.css`: primitives, semantic `--color-*` per theme with `--on-accent`/`--on-danger`, legacy aliases) under `@layer tokens`. Per-tab close/move buttons are pointer-only (`aria-hidden`, `tabindex=-1`); the workspace toolbar carries labelled Close and Move buttons for the active tab (touch screen readers), and keyboard users also have Delete and Alt+Shift+M. The axe baseline is empty: any violation fails. | Every text/background pair meets 4.5:1 in both themes (axe 85 → 0 violating nodes). A tablist may own only tabs. | The Phase 1 shell rebuilds the tab strip. |
| 2026-09-27 | Releases are cut by a `release` job on `main`: when `package.json` names a version with no tag, the job tags the deployed commit and publishes a GitHub Release from that version's CHANGELOG section. release-please and Conventional Commits are not adopted. | release-please needs GitHub Actions to open pull requests, which this repository does not allow; the version-bump job needs only `contents: write`. Without release-please, Conventional Commits would only change commit style for every agent. | Actions may open pull requests here, or releases become frequent enough that hand-written CHANGELOG sections lag. |
| 2026-09-27 | Budget policy v2: per-route gzip budgets in `test/bundle-budgets.json`, measured from Vite's build manifest, replace the raw 257,180-byte initial-shell ceiling. | Users download compressed bytes; one raw ceiling had 158 B of headroom and blocked a dependency update without saying which experience it cost. | A route needs a raise (budget log in performance_budgets.md). |
| 2026-09-27 | Browser tests run under Playwright Test with a fixed, forward-running clock (2026-09-16 11:00 America/New_York). | Retries, traces, and per-smoke reports; date fixtures had already broken CI once. The fixed clock exposed a tab-close race the real clock hid. | A test needs real time (set NOTEFORGE_E2E_REAL_CLOCK=1 to compare). |
| 2026-09-27 | Screenshot baselines are compared only inside `mcr.microsoft.com/playwright` at the lockfile's version. | Font rasterization differs by OS; one pinned image makes baselines exact. | Playwright is bumped: regenerate with the Visual baselines workflow. |
| 2026-09-27 | Accessibility is gated by an axe ratchet (`test/e2e/a11y-baseline.json`) rather than zero violations. | 85 known violating nodes predate the design system; a ratchet stops regressions now and Phase 1 takes the count to zero. | Phase 1 exit (axe clean): delete the baseline and require zero. |
| 2026-09-26 | Biome for lint and format; `node --test` for unit tests; canonical sync Option A (dispatch). | Roadmap §6 recommendations, taken in Phase 0 Sprint 2 and the 2026-09-25 sync work. | See roadmap §6. |
